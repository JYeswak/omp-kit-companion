# Release card: v0.2.103

0.2.103 fixes the two identity failures that stopped fleet seats from writing, takes the full test suite off the save path, and adds a remote runner that can take the release suite's Linux share off this Mac.

A seat restored without `AGENT_NAME` now takes its pane's registered name when it loads, so the write guard no longer refuses its own reserved paths with WRITE_OWN_NO_IDENTITY (ompkit-d5cd5, `1b49f8ccb6`). A native Task child's write is admitted when either the child's own name or its parent's holds the reservation (ompkit-1ra0d.41, `520c94b6c9`). A push no longer starts the complete suite in the background; it runs once per release, and a red release verdict now stops only that release instead of refusing every unrelated commit (Joshua J-2026-11-08-10 and -11; ompkit-kup44, `3d1ee2253a`). The release verdict can run its Linux share on the rch workers while this Mac runs only the macOS-only files, opt-in with `FULL_SUITE_REMOTE=1` (ompkit-qsktr, `8671d79b55`). Release assets are published gzip-compressed (ompkit-vpv8a, `2d82db22bd`), the shared CI poller authenticates with the existing gh credential (ompkit-u0lk2, `9d7a689b24`), and scratch cleanup reads `ps` start times as local time, so on hosts east of UTC a live owner's scratch is no longer judged abandoned (ompkit-ltawi, `d87e5889c9`). Linux 7-digit pids and GNU `stat` no longer break scratch and stale-worktree checks (ompkit-4tn55, `42999965c2`). `omp-kit slice-verify` no longer reports CLEAN for a failing run whose failures carry no names (ompkit-1ra0d.56, `88f70730f9`). A push whose change touches no gate script runs its affected tests once instead of twice, and the slice-verify test file dropped from 123 s to 6 s (ompkit-774u.71, `8e2ed798ba`).

Evidence: the main-role full suite passed on the exact tree `d02297ff60` of `8e2ed798ba` (`FULL-SUITE: VERDICT PASS`, local judge, 991 s); the cut installed and read back `omp-kit 0.2.103`, all 19 omp profiles link `releases/0.2.103`, and main advanced to 0.2.104 (`69123197be`) inside the cut. Stage times: preflight 3, source 4, verdict 1, build 14, sign 53, checksum 2, rule-gate 2, tag 6, draft 62, attest 53, verify 31, install 137, next-version 95; 463 s in total, against 535 s for 0.2.102. The gzip assets cut the draft upload from 137 s to 62 s; install is unchanged at 137 s.

Improvement applied: the remote verdict. Three Contabo workers ran 453 of 469 files and finished the same tree in 785 s (rv-4), against 1,000 to 1,800 s for a local run on a loaded Mac. Getting there found real defects: the gzip change had broken the N+2 update fixture on every platform (`b0bd2f4572`), and the remote run's open-file failures came from a root-only debugfs that made `lsof` warn on every call; the worker setup now fixes that and sets the workers to UTC like CI (`d87e5889c9`). Finished shards now record their timings when another shard stalls (`6fcfad4deb`). The remote run is not yet the judge of record: rv-5 failed six timing-budget tests on loaded 4-core workers that pass alone and on the Mac (ompkit-ltawi), so this release was judged on the Mac. Next levers: put the timing-budget tests on the Mac share, and measure a commit with the single-pass gate once this release is installed (before: 689 s for one 18-test file).

Known risk: contabo-2 twice failed to finish its shard under suite load (`wallclock-check.test.sh` hung; alone it passes in 35 s), so this release's verdict ran on the other three workers. Rollback: download the v0.2.102 release assets and run `omp-kit update --apply --yes --version 0.2.102 --index <abs path>/release-index.json --archive <abs path to the darwin archive>`; the 0.2.102 release directory stays installed under `~/.local/opt/omp-kit/releases/`.
