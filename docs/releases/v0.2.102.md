# Release card: v0.2.102

0.2.102 gives the lead a CI wake-up that is not a timed poll, makes the updater ready for gzip release assets, and lets the author handoff gate read the evidence `~/.claude` and other repositories actually produce. `omp-kit ci wait --repo OWNER/REPO --sha SHA` blocks on filesystem events from the shared CI cache and returns when a matching run completes, with one reconcile read after the watcher starts (ompkit-ob2zr). Published-release updates now fetch the release index first and accept `.tar` or `.tar.gz` archives whose bytes match the indexed digest, and reuse an interrupted, verified download (ompkit-vpv8a; packaging still emits `.tar`). Author handoff admits `~/.claude`'s own storegate GREEN marker and any repository's own complete GREEN fresh-gate observation, and its refusal names a command that exists (ompkit-774u.87). The native LSP certification check for a configured cold server is restored (ompkit-y3l36), and live-scenario failures now print bounded mock-transcript and OMP output tails (ompkit-1ra0d.49).

Evidence: the main-role full suite passed on the exact tree `6bb3d51b04` of `5cdb364c83` (`FULL-SUITE: VERDICT PASS`, 4,252 Bun tests, 73 shell and 35 Python suites); push CI run 42499926589 on `5cdb364c83` concluded success; the cut installed and read back `omp-kit 0.2.102`, and main advanced to 0.2.103 (`4a82e0c051`) inside the cut. Stage times: preflight 3, source 4, verdict 2, build 4, sign 56, checksum 3, rule-gate 1, tag 6, draft 137, attest 55, verify 50, install 133, next-version 81; 535 s in total, against 567 s for 0.2.101 and 638 s for 0.2.100.

Improvement applied: the CI wait (W1 item 1, ompkit-o3da). On `ad9093b946` and `f3e2dd79b8` it returned about 0.9 s after the poller recorded the completed run. On this release's own commit it never returned: the shared poller still calls GitHub anonymously, exhausts the 60-per-hour quota on six private repositories, and never recorded run 42499926589, so the lead read CI once with authenticated `gh` and stopped the wait. The poller authentication fix (ompkit-u0lk2, `9d7a689b24`) ships in 0.2.103. Next levers, each a bead: authenticate the poller (ompkit-u0lk2); publish gzip assets, since the draft upload (137 s) and install (133 s) remain the largest cut stages (ompkit-vpv8a, second half); and give omp-kit a pre-push gate that runs the affected tests, so omp-kit beads can reach review (ompkit-1ra0d.53, J-2026-11-08-05).
