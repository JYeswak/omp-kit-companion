# Release card: v0.2.104

0.2.104 does three things:
- Every agent now wakes on its own mail.
- The release notice now tells every seat to upgrade, including paused ones.
- The fleet safety rules and the standing law are back, after each rule was checked against how the fleet works now.

**Mail wake.** A seat in a fleet-watch repo now takes a turn when mail arrives for it, unless that repo's `.omp/fleet.json` sets `enabled:false` (Joshua J-2026-11-09-02; `93f1cd99c1`). Before this, a project stop or a paused goal silenced the wake. 295 messages never woke anyone, 110 of them to the lead.

**Upgrade notice.** Every seat that is behind the installed release is told to upgrade now, paused goal or stopped project included (J-2026-11-09-03; `5d26de9768`). Before this, a paused seat, the lead included, was told to stay paused and never moved to 0.2.100 or 0.2.103. The self-restart keeps an owner-paused goal paused.

**Rules.** Both changes are in `2d7c83cc15`.
- `omp-kit apply rules --fleet` installs the standing law again. It was removed in 0.2.99 before the contract that replaces it existed. Each of its rules was checked against later decisions and the current code. The 4 rules that later decisions replaced were dropped, so 50 remain. Each `mechanism=` now names the code that enforces the rule, or says `unenforced`.
- The fleet safety rules were replayed against 2 × 28,948 real tool calls from 2026-11-06 onward, using omp's own matcher.
  - `kit-no-force-push` and `kit-scratch-tmp` were dropped, because dcg and the fleet guard already block those actions.
  - The secret rule no longer fires on Infisical references.
  - The merge rule no longer fires on rebases inside builder worktrees. It had fired 17 times, all of them false.
  - The pattern-kill rule now also fires when the call states its intent before the command.

**Evidence.**
- **Verdict:** the main-role full suite passed on the exact tree `d16e5cd488` of `2d7c83cc15`, judged locally (`FULL-SUITE: VERDICT PASS`, 1,272 s run from the repo, 1,078 s from the release's exported script).
- **Install:** the cut installed and read back `omp-kit 0.2.104`.
- **Rules:** `omp-kit doctor --scope activation` reads all 10 fleet rules ON, with bytes matching the fleet manifest.
- **Next version:** `main` advanced to 0.2.105 (`133fb303ab`).
- **Stage times (s):** preflight 3, source 4, verdict 2, build 13, sign 49, checksum 2, rule-gate 2, tag 6, draft 62, attest 42, verify 23, install 139, next-version 112.

**Known risks.**
- **Remote judge:** the first cut ran its verdict on the remote Linux workers and was refused. That run failed timing-budget tests, a 30 s `package-release` timeout, one symlink-race test and one Python checker test. The same tree passes every file on this Mac. The remote run is still not the judge of record (ompkit-ltawi).
- **Wrong runtime label:** the remote FAIL was stored under this Mac's runtime label, so the local re-judge needed an explicit `--rerun-reason`.
- **Validator model:** the rule validators ran on Opus, not Sol, because the Sol setting is not applied. The rule corpus check and the tests were re-run by the lead; the replay of real tool calls has not been repeated by an independent grader.
- **Stale hooks:** activation still reports stale or missing hook members in uds, localbench, zestroku, clutterfreespaces.ios and skill-library-growth (HOOKREFRESH1).

**Rollback:** download the v0.2.103 release assets and run `omp-kit update --apply --yes --version 0.2.103 --index <abs path>/release-index.json --archive <abs path to the darwin archive>`; the 0.2.103 release directory stays installed under `~/.local/opt/omp-kit/releases/`. To take the fleet rules back out, run `omp-kit undo fb6a510d-4dd7-4e29-a871-12b5d23345df --yes`.
