- `omp-kit verify` now provisions JavaScript dependencies on the export before replaying boxes: for each directory holding a lockfile that a box's cwd is in or under, it installs frozen from that lockfile (`bun install --frozen-lockfile`, `npm ci`, `pnpm install --frozen-lockfile`, `yarn install --frozen-lockfile`, `deno install --frozen`), offline-first from your package cache. A missing or out-of-date lockfile is a named `DEPENDENCIES_NOT_LOCKED` refusal, never a silent pass; the working repo's `node_modules` is never copied.
- After each install the provisioned `node_modules/.bin` fronts the replay `PATH`, so bare runner binaries (`vitest run`, `npx vitest`) resolve the lockfile-pinned binary instead of a caller-global one; `npx`/`bunx`/`corepack` boxes trigger provisioning, and a `deno` box in a project without `deno.lock` is refused.
- `NODE_PATH` and `NODE_OPTIONS` no longer reach the replay, so caller-side package closures cannot leak into it; dependency installs run with caller tokens and registry auth scrubbed from the environment (install scripts still run, `HOME` and package caches stay so offline installs work).
- pnpm installs pin `--store-dir` to the user's own store, so a replay on a different filesystem never drops a project-local `.pnpm-store` into the tree under test.
