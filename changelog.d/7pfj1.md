### Added
- `omp-kit doctor --scope access` names an unanswered macOS permission prompt (TCCPROMPT1). On 2026-11-21 a dialog ("omp-kit would like to access files on a network volume") sat unanswered on the Studio screen; while it was pending, `open()` on `~/Desktop`, `~/Documents` and the ovnfs mount blocked, every new omp start hung at `Still starting after Ns — phase: preloadPluginRoots` (omp resolves the project path of each project-scope Claude plugin entry on every start), and four seats could not restart for an hour with no tool naming the cause. The scope opens the two protected folders and every network or removable mount with the kit's own binary under a 5 s deadline: a blocked open is `TCC_CONSENT_PENDING` (status `FAIL`, with the action "a person answers the dialog; hold seat restarts and the kit-update job"), a permission refusal is `DENIED` (status `DEGRADED`), an absent folder is not a finding, and an unreadable mount table is `UNVERIFIED`, never `OK`. The probe command is now shared with the scratch reaper (`selfOpenProbe`).
