### Fixed
- `omp-kit update --apply` no longer reports every service as failed. The manifest loop judged each `omp-kit service install <job> --apply --yes --json` by a top-level numeric `code` that the printed envelope never carries (the envelope is `{ok, tool_version, data, errors, ...}`; the exit code is not printed), so all 19 services read as failed although they exited 0 with `ok:true` ("Identical bytes and loaded; no-op"), and every update that reached the loop ended `FINDINGS`, exit 1. A service is now applied when its process exits 0 and its envelope says `ok: true`; exit 0 with `ok:false`, a non-zero exit and unparsable output each stay failed. Found on the 0.2.140 install (0.2.139 never reached the loop: its postcheck stopped first); the tests had stubbed `{code: 0}`, a shape no real run prints, and now stub the real envelope.
