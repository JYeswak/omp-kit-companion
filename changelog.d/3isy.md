### Fixed

- A kit update no longer ends `PARTIAL` (`KIT_POSTCHECK_FAILED`, "Operator file changed during isolated test") on the running fleet's own state. The 0.2.138 and 0.2.139 installs each needed a hand `omp-kit update --reconcile` because the postcheck judged files that running seats and chief ticks rewrite every few seconds: `chief/**` (tick, fleet-guard and watchdog state), `model-evidence/*.jsonl` and `native-tool-attempts.json` under the kit state root. They are now declared live-fleet state in the operator snapshot (`src/operator-snapshot.ts`), so the postcheck neither hashes nor judges them, and `scripts/release-local.sh` carries the same paths in its live-writer reconciliation class, because an install is judged by the PREVIOUS version's postcheck and the product change only helps the install after next. Look-alike names (`chief-notes.json`, `model-evidence.json`, a path with `..`) and every other kit-owned file, such as a receipt, are still reported and still refuse.
