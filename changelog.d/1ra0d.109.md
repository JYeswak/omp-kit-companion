### Fixed

- A main-role `scripts/full-suite-verdict.sh` run can no longer qualify a tree with the wrong judge or the wrong declared suite. `JUDGE_NOT_CANDIDATE`: when the candidate carries the judging closure and it differs from the scripts being run (`suite-metrics.py identity` over `SCRIPT_DIR`), the run refuses before any suite starts and says to launch from a clean checkout of the commit; launched from a checkout on another HEAD it judged a different suite and produced a record no release could read back (the 0.2.139 verdict launched from the live working tree, 2026-11-21). A tree with no judging closure at all (a fixture) has no identity to compare and is left to the reader's own judge-root check. `SUITE_NOT_IN_COMMIT`: when the staging directory declares test files the commit's tree lacks (an untracked leftover in `--archive-dir`), the run refuses naming them, instead of every worker shard refusing them one by one. `SHARDEVIDENCE1`: when a remote shard is INCOMPLETE, the failing rows of every shard that did finish now reach the verdict's stderr (the verdict used to print only the INCOMPLETE lines), because the worker's run directory is reaped right after its evidence is fetched and an unrecovered failing shard cannot be told from a flake (the 13100edb20 `.46` FAIL was lost that way). `full-suite-verdict-guards.test.sh` plants a drifted judging closure and an untracked leftover, keeps an exact-extract control and a closure-less control, and `full-suite-remote.test.ts` gains the `SHARDEVIDENCE1` case.
