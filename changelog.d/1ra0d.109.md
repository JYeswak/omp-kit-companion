### Fixed
- Three `tests/cli/test-runner.test.ts` witnesses no longer fail on omp 19.1.0 (RELFLAKE1). omp 19.1.0 (Tern bundle, installed 2026-11-21 07:51 local) stopped inspecting the partial arguments of a rule that cannot interrupt (`interruptMode: never`) and leaves it to the `*_end` check, so the matcher harness observed `prefix.phase: "final"` where the fixtures expected the streamed prefix (`stream` at position 21 of 22 for the bash-wire rule): the exact-tree verdicts of 0.2.145's candidate failed `observes bash arguments on JSON wire`, `observes a selected external witness through the native matcher` and `completed payload remains quiet when an earlier streamed prefix fired` on the Studio. The three fixture rules now use `interruptMode: always`, which streams on every omp the kit certifies; production rules are unaffected (the full live suite passes 151/151 on omp 19.1.0).
- `scripts/e2e-live.sh` reruns a live scenario once when omp exits 1 right after `TTSR matched rule` and the scenario saw too few model requests (RELFLAKE1). That signature failed the hosted ladder on a91da36e73 (`derived-facts-version-fire`, 1 model request, rule named 0x) and the 0.2.144 kit-update postcheck on the Studio (`test-source-runtime-fire`), each once, both under load and never in 80 idle runs; it cost one red main and one rollback of a healthy release. The rerun uses a fresh home, project and mock, prints `FLAKY_OMP_TTSR_ABORT scenario=<id>` so the event stays counted, and a second failure, any other exit code, a failure without the TTSR line, or `OMP_KIT_E2E_TTSR_RETRY=0` is the verdict.
- `scripts/regex-budget.ts` judges the bash stream the way omp 19.1.0 runs it (RELFLAKE1). omp 19.1.0 compiles rule conditions to a linear matcher (`LinearRegExp`), skips rules that cannot interrupt a tool call in partial checks and rescans only the changed region, so the gate's bare-regex prefix sweep measured a cost omp no longer pays: the kit pack read 1495 ms against a 966 ms budget on 19.1.0 (1078 ms against 1344 on 19.0.1) and the catastrophic fixtures (`(a+)+b`, `a(a|aa)+b`) stopped being exponential, so `regex-budget.test.ts` and, through the stage, `package-release` named-case and `package-release-live` failed on every Studio verdict since the omp update, at any load (same host, same minute, load 50: `OMP_SRC` 19.0.1 passes both fixtures, 19.1.0 fails both, four alternating runs). The gate now detects the engine from the manager it measures (`TtsrManager.prototype.interruptsToolStream`) and, where present, times each bash stream condition through omp's own `TtsrManager` (a partial check per 16-byte delta, then the final check); older omp keeps the prefix sweep. The write/edit stream, the near-miss ceilings and the reference scaling are unchanged. Measured on this Mac, installed 19.1.0: live stream 138 ms against 965; 19.0.1 and 18.11.3 PASS as before. Fixtures that must stay exponential compile with the native `RegExp` (`compile: "native"`). New tests pin the detection, the delta count of the manager mode (8 against 7), the fail-closed missing rule file and that a manager-timed stream has no sweep baseline for the scaled reference to admit.
