- The `kit-update` launchd job and systemd unit keep their configured update settings across re-renders: reinstalling the service or the kit from a shell without `OMP_KIT_UPDATE_*` no longer writes a job file with no settings (previously every run then exited 2 with `KIT_UPDATE_JOB_CONFIG`). Supplying new settings still replaces the installed ones.
- Each `kit-update` run now prunes old `kit-update-job-<uuid>.json` run records to the newest 30, so the state directory stops growing by thousands of files; the single newest non-terminal `PENDING` receipt is always kept as the recovery trail, and files that are not run records are never touched.
