- `omp-kit apply policy` now sets `ttsr.repeatGap` to 1 instead of 0, so a rule whose text says to run the command again unchanged (for example the Tern overseer-worktrees rule) no longer interrupts the identical rerun forever; the immediate rerun is admitted and a genuinely later occurrence still fires. If your profiles still show `repeatGap 0`, re-run `omp-kit apply policy` to pick up the fixed value.
