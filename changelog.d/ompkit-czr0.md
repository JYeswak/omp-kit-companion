- Tern-managed OMP works with the kit. Tern (by OMP's authors) installs `omp` as one compiled binary with no TypeScript beside it, so `omp-kit test` reported `UNVERIFIED BUNDLED_RUNTIME_UNAVAILABLE` and the pre-push gate failed with "cannot locate the omp <version> package source". When no installed package of the exact same version exists, the kit now installs `@oh-my-pi/pi-coding-agent@<that version>` from npm into `~/.local/opt/omp-kit/omp-src/<version>/` (`bun add --exact --ignore-scripts`; bun checks each tarball's sha512, and the lockfile integrity is recorded in `.verified.json`). An entry is served only when its manifest names the requested version; any other version is still refused. The two newest versions are kept. `OMP_KIT_OMP_SRC_FETCH=0` disables installs (a verified entry is still used); `OMP_KIT_OMP_SRC_CACHE` moves the cache.
- `fleet-restart`: panes running Tern's compiled omp are detected as agents. ps shows a compiled omp by the name it was invoked by (`omp --profile x`) or by its versioned Tern path, not as `bun …/omp`, so such panes were classified as shells and skipped by `plan`, `verify` and `sitrep`. Only the process's own first token counts, so the `zsh -lc "… && omp …"` respawn wrapper and `omp-kit` are never mistaken for agents.
