- `kit-test-skip` no longer refuses `@unittest.skipUnless` (a missing tool, SDK, or platform). A bare `@unittest.skip(` still stops the edit.
- `kit-unverified-done` no longer treats a plan sentence such as a future run that ought to succeed as a result claim. "the tests pass", "is now fixed", "should work", and "it will fix" still stop the message.
- `kit-probe-readable-facts` no longer treats an edit-tool path header, an unspaced fleet-registry `"repo"` field, or an extensions search path as a hand-copied probe fact. A home path on a line that also contains the word session still stops the edit. Private-path exemptions are checked only after a matching `/Users/` or `/home/` prefix, avoiding repeated lookbehind scans on streamed non-path content.
- `kit-close-needs-evidence` no longer treats `br close` inside an intent, a question, or a `grep` pattern as a close. A real `br close` without `--reason` still stops.
- `kit-no-double-quoted-substitution` no longer jumps from a `br` verb into a later tool field, and a read-only `$(br show)` capture is not a mutation. A double-quoted backtick or `$(` on `br create`, `br update`, `br comments add`, or `git commit -m` still stops the call.
