### Fixed
- `scripts/affected-tests.ts` now names a suite after what it judges (NAMEDSUITE1): `tests/cli/<stem>.test.{ts,sh}` is selected, one hop, when `scripts/<stem>.{sh,py,ts}`, `src/<stem>.ts` or `extensions/<stem>.ts` changes, even when the suite builds that path at run time and no literal reference shows the edge. `tests/cli/br-shim.test.sh` is the case that escaped: a change to `scripts/br-shim.sh` (REVIEWROUTE1) selected 32 suites but not it, the clone gate and hosted CI passed, and the release verdict found five failing cases. It adds selection only, no refusal.
- The same in_review handoff admission now also requires the bead's author to have written a `Lesson:` comment (or to write one in the handoff `--transition-comment`), the predicate `omp-kit verify` applies before it replays anything, so work that verify would refuse with `LESSON_MISSING` stays out of review. The author is the bead's assignee, else its creator; a Lesson from anyone else, or one only in `--append-notes`, does not count. Both refusals now carry verify's own codes: `HANDOFF_UNGATED NOT_PUBLISHED` for an unpublished source and `HANDOFF_UNGATED LESSON_MISSING` for a missing Lesson. Write the Lesson once with the DONE line, for example `--transition-comment $'DONE /path@<sha>: what landed\nLesson: what this taught'`.
