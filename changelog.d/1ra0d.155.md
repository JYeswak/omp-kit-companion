- `omp-kit tools update ovnfs --plan|--apply`: resolves the newest stencil-hq/ovnfs release (explicit `omp-kit/<version>` User-Agent; `GITHUB_TOKEN`/`GH_TOKEN` used when present, never printed), verifies the asset against the publisher checksums, keeps the previous binary as `ovnfs.prev`, refreshes the release-tagged ovnfs skill, then swaps the daemon. The new daemon is proven loaded; when its checkout count drifted the update still accepts if every pre-swap live checkout persists (reporting the new count) and rolls back only if the daemon is unproven or checkouts vanished. Failure restores `ovnfs.prev`, restarts, and reports the serve.log blocker lines with which uppers blocked (live vs orphan), without changing any file mode under the daemon state; a symlinked binary path is refused, never written through.
- New `tool-update` service job (every 6 h, runAtLoad false): runs the update with --apply; under high load it lands the binary and skill but defers the daemon swap; an offline publisher lookup is a quiet `LOOKUP_UNAVAILABLE` no-op tick instead of a red finding.
- The tools manifest pin now tracks the installed ovnfs 0.4.0 release instead of claiming 0.1.1.
- Skill destination: `OMP_KIT_OVNFS_SKILL_DST` wins; otherwise the packaged `config/ovnfs.json` `skill_store_subpath` joined under HOME.
