- The push gate no longer refuses a commit that only deletes code: a deleted file cannot have a covering test, so tip-absent paths are excluded from the changed-code list in both the fresh gate and the declared affected-tests gate, and a deletion-only push passes with a `deleted-only: N paths` note. Deleting one file does not excuse the rest: a push that deletes a file and still changes an uncovered file is still refused naming only the kept file, and suites a kept change selects still run.
- Deleting a module its code still imports no longer passes untested: each deleted path's tip importers (relative import/require/from specifiers with or without an extension, same-package-dir Python stem imports plus `scripts/<stem>` users, shell `source`/`. ` operands) join the changed set before selection, so the importers' suites run even when the importers themselves are unchanged, or the existing `NO_AFFECTED_TESTS` refusal names the importer when no suite reaches it. Dynamic/computed imports are out of scope: such an importer's own suite must be selected some other way. A deleted shell entry point or Rust module with no importer and no covering rule fails closed instead of passing silently, and an unreadable tip file refuses the importer scan rather than being skipped.
