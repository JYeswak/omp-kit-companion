### Fixed
- Owned-scratch reaper (SCRATCHREAP2): a reaper run over trees that include ovnfs/NFS checkout paths no longer fails every action with `atomic-quarantine-failed`. A cross-device rename now falls back to a same-filesystem quarantine beside the source root (instead of failing), with the same inode/owner/users/open-file proofs, and the expiry sweep drains those entries too.
- Owned-scratch reaper (SCRATCHREAP2): quarantine or removal of an owned directory now waits for proven owner death or pid reuse (process-start incarnation, then seat liveness). A live or unproven owner is left in place with its evidence and is never removed, and a release marker alone no longer quarantines a live owner's directory.
- Owned-scratch reaper (SCRATCHREAP2): large censuses are worked in bounded batches with persisted progress. A batch interrupted by its deadline keeps its completed entries, revisits the rest on the next run, always writes its receipt, and no longer spends a blown deadline on orphan or bun-build work.
- Owned-scratch reaper (SCRATCHREAP2): deleting an expired quarantine entry blocked by a macOS user-immutable flag (`uchg`/`schg`) is now a refusal (`user-immutable`, run stays COMPLETE with `refused_count`) instead of a failure; every other delete failure still fails the run.
- The SCRATCHREAP2 cross-device quarantine test runs only on request (`OMP_KIT_XDEVICE_E2E=1`, macOS): it failed hosted CI and the Linux release shards on `eace848150` (no ovnfs there), and under load its ovnfs fixture leaves a stale NFS mount that hangs the gate.
